## 1 本章总览

前面已经完成：词法分析器、递归下降+Pratt解析器、AST、变量、if-else、return、函数、高阶函数、闭包。

Monkey早期只有两种基础值类型：`Integer`整数、`Boolean`布尔。
本章新增语言数据类型与内置桥接函数：

| 新增类型 | 说明 | 特性 |
|---------|------|------|
| 字符串 `String` | 字面量、`+`拼接 | 复用Go string |
| 动态数组 `Array` | 多类型混合、下标索引 | 动态切片 |
| 哈希字典 `Hash` | 键值对，key仅允许string/integer/boolean | HashKey映射 |
| 内置函数 `Builtin` | Go与Monkey之间的桥梁 | 宿主语言能力 |

**内置函数清单**：
- `len()`：获取字符串、数组长度
- `first()`、`last()`：取数组首尾元素
- `rest()`：返回去掉首元素的新数组（不可变）
- `push()`：追加元素，返回新数组（不可变，不修改原数组）
- `puts()`：控制台打印输出，返回`null`

> 实现思路：所有运行时对象直接复用Go宿主语言底层存储，不手动实现内存、编码。

**整体流水线统一**：
```
源码文本 → Lexer产出Token → Parser构建AST节点 → Evaluator遍历AST产出运行时Object对象
```

## 2 设计思路：四层分层架构

每种数据类型都在四层有对应的处理逻辑，职责单一、分层清晰：

```
Layer 1: Token     — 词法识别，产出 token 类型
Layer 2: AST       — 语法结构，定义表达式/语句节点
Layer 3: Object    — 运行时对象，包裹宿主语言类型
Layer 4: Evaluator — 求值逻辑，AST节点 → 运行时对象
```

### 为什么需要四层分离？

| 层次 | 关注点 | 职责 |
|------|--------|------|
| Token | 文本切分 | 把源码字符串切成最小语义单元 |
| AST | 语法结构 | 把Token流组织成树形结构，表达语法关系 |
| Object | 运行时存储 | 实际参与计算的对象，复用宿主语言存储 |
| Evaluator | 执行逻辑 | 遍历AST，产出Object，执行运算 |

**好处**：
- 每层只做一件事，职责清晰
- 新增类型只需在各层添加对应处理
- 测试可以按层隔离

## 3 字符串类型实现

### 3.1 整体流程

```
源码: "hello world"
       ↓
Lexer: 识别双引号，产出 token.STRING
       ↓
Parser: 注册前缀解析函数，生成 ast.StringLiteral 节点
       ↓
Evaluator: 匹配 StringLiteral，产出 object.String 运行时对象
```

### 3.2 Lexer词法（识别字符串）

字符串字面量以双引号包裹，词法分析器需要特殊处理：
- 遇到左引号`"`，开始读取字符直到右引号`"`
- 输出 `Token{Type: STRING, Literal: "hello world"}`

> 注意：`Literal` 保存带引号的原始文本

### 3.3 AST层（StringLiteral节点）

```go
type StringLiteral struct {
    Token token.Token  // 带双引号的原始文本
    Value string       // Go原生string，去掉引号后的内容
}
```

> 和 `IntegerLiteral` 结构几乎一样：Token保存原始文本，Value保存解析后的值。

### 3.4 Parser解析（注册前缀函数）

在 `New()` 中注册：
```go
p.registerPrefix(token.STRING, p.parseStringLiteral)

func (p *Parser) parseStringLiteral() ast.Expression {
    return &ast.StringLiteral{Token: p.curToken, Value: p.curToken.Literal}
}
```

> Parser只负责把token的字面量存入AST，**不做求值**。

### 3.5 Object运行时对象（String）

```go
const STRING_OBJ = "STRING"

type String struct {
    Value string  // 包裹Go原生string
}
```

> 核心：直接包裹 Go 原生 `string` 类型，不自己造存储。

### 3.6 Evaluator求值

```go
case *ast.StringLiteral:
    return &object.String{Value: node.Value}
```

### 3.7 字符串拼接 `"+"`

字符串拼接是 **中缀表达式**，走 `evalInfixExpression` 逻辑。

**设计决策**：
1. 仅当左右两边都是 `STRING_OBJ`，允许 `+` 做拼接
2. 其他运算符（`- * /`）直接返回运行时错误
3. 类型不匹配（字符串+数字）报 `type mismatch` 错误

```go
case left.Type() == object.STRING_OBJ && right.Type() == object.STRING_OBJ:
    return evalStringInfixExpression(operator, left, right)
```

## 4 内置函数基础模型 Builtin

### 4.1 问题：为什么需要内置函数？

内置函数充当 **Monkey 语言和宿主语言 Go 之间的桥梁**：

| 函数类型 | 来源 | 函数体 | 执行方式 |
|---------|------|--------|---------|
| 用户自定义函数 | Monkey代码 `fn(){}` | AST节点 | evaluator递归求值 |
| 内置函数 | Go代码预定义 | Go原生函数 | 直接调用Go函数 |

示例：`len("hello")` 需要获取字符串长度，Monkey 用户自己写代码做不到，必须由宿主语言提供。

### 4.2 设计：Builtin对象

把Go函数包装成Monkey对象：

```go
const BUILTIN_OBJ = "BUILTIN"

type BuiltinFunction func(args ...object.Object) object.Object
type Builtin struct {
    Fn BuiltinFunction  // 保存实际执行的Go函数
}
```

> 可变参数 `...object.Object`：接收任意个数参数，内部自己校验参数数量。

### 4.3 标识符查找顺序

当求值标识符时，查找顺序：

```
1. 当前环境 env.Get(name)  — 优先查找变量
2. 全局内置函数map         — 变量找不到，再查内置
3. 返回 "identifier not found"
```

> 用户可以自己定义同名变量**覆盖**内置函数：`let len = fn(x){x}` 之后 `len(5)` 调用的是用户函数。

### 4.4 函数调用分发

函数调用统一入口 `applyFunction` 做类型分支：

```go
func applyFunction(fn object.Object, args []object.Object) object.Object {
    switch fn := fn.(type) {
    case *object.Function:
        // 用户函数：扩展闭包环境，递归求值AST函数体
    case *object.Builtin:
        return fn.Fn(args...)  // 直接调用Go函数
    default:
        return newError("not a function: %s", fn.Type())
    }
}
```

### 4.5 实现第一个内置函数 len()

```go
var builtinLen = func(args ...object.Object) object.Object {
    if len(args) != 1 {
        return newError("wrong number of arguments. got=%d, want=1", len(args))
    }
    switch arg := args[0].(type) {
    case *String:
        return &Integer{Value: int64(len(arg.Value))}
    default:
        return newError("argument to len not supported, got %s", arg.Type())
    }
}
```

**核心逻辑**：
1. 校验参数个数
2. 根据参数类型做分支
3. 返回值必须是 `object.Object`，不能是 Go 原生值

## 5 数组 Array 实现

### 5.1 问题：数组需要什么能力？

- 动态大小：元素个数不确定
- 多类型混合：数字、字符串、函数、数组都可以存
- 索引访问：`arr[0]` 获取元素

### 5.2 设计：IndexExpression 通用索引节点

索引表达式同时服务数组和哈希，设计一个通用的 `IndexExpression` 节点：

```go
type IndexExpression struct {
    Token token.Token // [
    Left  ast.Expression  // 被索引的对象（数组/哈希）
    Index ast.Expression  // 索引表达式
}
```

> 通过 `Left` 的运行时类型做分支分发。

### 5.3 Parser：复用表达式列表解析

重构通用工具函数 `parseExpressionList(endToken)`：
- 解析逗号分隔的表达式列表
- 传入结束token（`RBRACKET` 或 `RPAREN`）
- 同时给数组字面量和函数调用参数复用

### 5.4 Object运行时对象

```go
const ARRAY_OBJ = "ARRAY"

type Array struct {
    Elements []object.Object  // 元素可以是任意Object类型
}
```

### 5.5 Evaluator：批量求值 + 索引访问

**数组字面量求值**：
- 遍历 `Elements` 表达式列表
- 对每个表达式调用 `Eval()`
- 包装为 `*object.Array`

**索引访问求值**：
- 分别求值 `Left`（数组）和 `Index`（下标）
- 校验下标是整数、范围合法
- 越界或负下标返回 `NULL`

### 5.6 数组内置函数（全部不可变）

| 函数 | 说明 | 边界 |
|------|------|------|
| `len(arr)` | 元素个数 | 支持数组、字符串 |
| `first(arr)` | 第一个元素 | 空数组返回NULL |
| `last(arr)` | 最后一个元素 | 空数组返回NULL |
| `rest(arr)` | 去掉首元素的新数组 | 空数组返回NULL |
| `push(arr, elem)` | 追加元素返回新数组 | 不修改原数组 |

> **不可变原则**：所有数组操作返回新数组，不修改原数组。

## 6 Hash哈希（字典）完整实现

### 6.1 问题：Go map key的困境

Go的map key必须是可比较类型。Monkey对象是指针：
- `"hello"` 字面量在不同位置产生不同指针
- `str1 == str2` 比较的是指针，不是内容

直接用对象指针做key会导致查询失败。

### 6.2 设计：HashKey + Hashable接口

**解决方案**：

```go
type HashKey struct {
    Type  ObjectType   // 防止不同类型哈希碰撞
    Value uint64       // 哈希值
}

type Hashable interface {
    HashKey() HashKey  // 只有实现此接口才能作为hash key
}
```

**实现Hashable**：
- Boolean：true→1，false→0
- Integer：直接转uint64
- String：使用 `fnv-1a` 64位哈希算法

> Array、Function、Hash **不实现Hashable接口**，用作key运行时报错。

### 6.3 HashPair：为什么需要保存原始key？

```go
type HashPair struct {
    Key   object.Object  // 原始key对象，用于打印输出
    Value object.Object
}
```

> 必须保存原始key对象，否则无法格式化打印哈希内容（如 `{name: "Tom"}`）。

### 6.4 语法错误 vs 运行时错误

| 类型 | 阶段 | 示例 |
|------|------|------|
| 语法错误 | Parser | 缺少冒号、括号不匹配 |
| 运行时错误 | Evaluator | key类型不支持哈希（数组作为key） |

```monkey
// 语法合法，AST生成成功，但运行时报错
{arr: 100}  // Error: unusable as hash key: ARRAY
```

### 6.5 哈希索引取值

复用已有的 `IndexExpression` 节点，在 `evalIndexExpression` 增加 `HASH_OBJ` 分支：

```go
func evalHashIndexExpression(hash, index object.Object) object.Object {
    hashObj := hash.(*object.Hash)
    hashable := index.(object.Hashable)  // 接口断言
    if !ok {
        return newError("unusable as hash key: %s", index.Type())
    }
    pair, ok := hashObj.Pairs[hashable.HashKey()]
    if !ok {
        return NULL  // key不存在返回NULL
    }
    return pair.Value
}
```

## 7 puts打印内置函数

```go
"puts": &object.Builtin{
    Fn: func(args ...object.Object) object.Object {
        for _, arg := range args {
            fmt.Println(arg.Inspect())
        }
        return object.NULL  // 无返回值统一返回NULL
    },
},
```

> Monkey全部是表达式，函数调用必须返回对象，禁止返回nil。

## 9 关键坑点复盘

| 坑点 | 说明 |
|------|------|
| Hash不用对象指针做key | 设计`HashKey`结构体解决指针相等问题 |
| 动态key类型校验在运行时 | Parser只检查语法，key类型校验推迟到Evaluator |
| HashPair保存原始key对象 | 否则无法格式化打印 |
| 数组内置函数不可变 | rest/push返回新数组，原数组不变 |
| 内置函数查找顺序 | 环境变量优先，后查内置map |
| 所有表达式必须返回Object | 无返回语义统一返回NULL，禁止nil |
| IndexExpression服务多种类型 | 依靠Left的Type()做分支分发 |
